     9→# 00. INSTRUCTIONS POUR L'AGENT DE DÉVELOPPEMENT
    10→
    11→> **Lis intégralement ce document avant d'écrire la moindre ligne de code.**
    12→
    13→## 00.1 Ta mission
    14→
    15→Tu dois construire **l'intégralité** de la plateforme INFOSPRO.NET décrite ci-dessous : base de données, backend serverless, API, site public (front-office), tableau de bord d'administration (back-office), moteur SEO, régie publicitaire, module newsletter, et toute l'infrastructure associée.
    16→
    17→Ce document est **normatif**. Chaque section contient des spécifications directement implémentables : schéma SQL, routes d'API, arborescence de fichiers, jetons de design, noms de composants, règles métier, critères d'acceptation.
    18→
    19→## 00.2 Règles absolues
    20→
    21→1. **Ne simplifie rien.** Si une fonctionnalité est décrite, elle doit être implémentée entièrement, pas en version « démo ».
    22→2. **Aucune donnée en dur.** Tout texte affiché sur le site public doit provenir de la base de données ou de la table `translations`. Aucun titre de rubrique, aucun libellé de menu, aucune adresse e-mail, aucun lien social ne doit être écrit dans le code.
    23→3. **Respecte les noms.** Les noms de tables, colonnes, routes, composants et variables d'environnement donnés ici sont contractuels. Ne les renomme pas.
    24→4. **TypeScript strict.** `strict: true`, aucun `any` implicite, aucun `@ts-ignore` sans commentaire justificatif.
    25→5. **Pas de `localStorage` pour des données métier.** Uniquement pour les préférences d'affichage (thème, mode données réduites).
    26→6. **Sécurité côté serveur.** Chaque vérification de permission se fait sur le serveur. Masquer un bouton n'est jamais une protection.
    27→7. **Mobile d'abord.** Toute interface est conçue d'abord pour un écran de 360 px, puis élargie.
    28→8. **Performance dès le premier commit.** Ne code pas « on optimisera après ». Les budgets de la section 16 sont bloquants.
    29→9. **Si une information manque**, choisis l'option la plus proche de ce qui se fait sur BBC News, The Economist ou Le Monde, et documente ton choix dans `/docs/DECISIONS.md`.
    30→10. **Langue du produit :** français. Langue du code (variables, fonctions) : anglais. Commentaires : français.
    31→
    32→## 00.3 Ordre d'exécution imposé
    33→
    34→Construis dans cet ordre. Ne passe à la phase suivante qu'une fois la précédente fonctionnelle et testée.
    35→
    36→```
    37→PHASE 1  Socle          → repo, config, DB, migrations, seed, auth, RBAC
    38→PHASE 2  Back-office    → CRUD articles, éditeur blocs, médiathèque, taxonomies

    47→Le détail de chaque phase, avec ses critères d'acceptation, figure en **section 20**.

    49→## 00.4 Identité visuelle imposée
    50→
    51→- **Couleurs :** blanc, noir, rouge — strictement. Aucune autre couleur décorative.
    52→- **Rouge de marque :** `#C8102E`

    68→# 01. CONTEXTE ET OBJECTIFS
    69→
    70→## 01.1 Nature du produit
    71→
    72→Site d'information généraliste, national et international, produit depuis la Guinée, avec ambition de qualité comparable aux grands médias mondiaux. Contenus en français au lancement, architecture multilingue native (anglais en phase 2, arabe RTL prévu).
    73→
    74→## 01.2 Contraintes structurantes
    75→
    76→| Contrainte | Conséquence technique directe |
    77→|---|---|
    78→| Audience majoritairement sur 3G/4G instable, forfaits data coûteux | Budget strict de poids de page, mode données réduites, ISR agressif |
    79→| Parc Android d'entrée de gamme (4 Go RAM) | Animations `transform`/`opacity` uniquement, JS initial < 180 Ko |
    80→| Rédaction non technique | Back-office en français, vocabulaire de presse, formation en 4 h |
    81→| Pics d'audience imprévisibles (élections, crises) | Serverless élastique, cache en périphérie, pas de serveur à dimensionner |
    82→| Extension future (abonnements, annonces, emploi) | Schéma relationnel extensible, pas de refonte nécessaire |
    83→| Lecteurs répartis sur 4 continents | CDN mondial, fuseaux horaires, éditions géographiques |
    84→
    85→## 01.3 Objectifs mesurables à 12 mois
    86→
    87→| Objectif | Indicateur | Cible |
    88→|---|---|---|
    89→| Audience | Visiteurs uniques mensuels | ≥ 300 000, dont 25 % hors Guinée |
    90→| Fidélisation | Abonnés newsletter actifs | ≥ 20 000 · ouverture ≥ 35 % |
    91→| SEO | Part du trafic organique | ≥ 45 % |
    92→| Performance | Core Web Vitals terrain p75 | LCP < 2,0 s · INP < 200 ms · CLS < 0,1 |
    93→| Disponibilité | Uptime mensuel | ≥ 99,9 % |
    94→| Autonomie | Modifications sans développeur | 100 % du contenu, 95 % de la mise en page |
    95→| Monétisation | Emplacements publicitaires actifs | ≥ 18 formats distincts |
    96→| Productivité | Délai de publication d'une brève | < 3 minutes |

   110→
   111→## 02.1 Choix technologiques
   112→
   113→| Couche | Technologie | Version | Note |
   114→|---|---|---|---|
   115→| Framework | **Next.js** App Router | 15.x | React Server Components par défaut |
   116→| Langage | **TypeScript** | 5.x | `strict: true` |
   117→| UI | **React** | 19.x | — |
   118→| Styles | **Tailwind CSS** | 4.x | Jetons de design en variables CSS |
   119→| Animations | **Framer Motion** (`motion`) | 11.x+ | + transitions CSS natives pour le simple |
   120→| Base de données | **PostgreSQL** | 16+ | Serverless : Neon, Supabase, ou Aurora Serverless v2 |
   121→| ORM | **Prisma** | 5.x+ | Alternative acceptée : Drizzle |
   122→| Pool de connexions | PgBouncer / pooler intégré | — | **Obligatoire** en serverless |
   123→| Auth | **Auth.js (NextAuth)** v5 | 5.x | Credentials + TOTP 2FA |
   124→| Validation | **Zod** | 3.x | Schémas partagés client/serveur |
   125→| Recherche | **Meilisearch** | 1.x | Repli : PostgreSQL FTS + `pg_trgm` |
   126→| Cache / compteurs | **Redis serverless** (Upstash) | — | Vues, sessions, rate limit |
   127→| Stockage objet | **S3** ou **Cloudflare R2** | — | Médias |
   128→| Transformation images | `next/image` + service de transformation | — | AVIF/WebP, 6 largeurs |
   129→| Vidéo | **Mux** ou **Cloudflare Stream** | — | HLS adaptatif, sous-titres |
   130→| E-mail | **Resend** ou **Amazon SES** | — | SPF/DKIM/DMARC obligatoires |
   131→| Files & cron | **QStash** ou **Inngest** | — | Tâches asynchrones |
   132→| Éditeur riche | **TipTap** | 2.x | Sortie **JSON blocs**, jamais HTML brut |
   133→| Formulaires | **React Hook Form** + Zod | — | — |
   134→| Tables admin | **TanStack Table** | 8.x | — |
   135→| Graphiques | **Recharts** | — | Dashboards |
   136→| Tests unitaires | **Vitest** | — | — |
   137→| Tests E2E | **Playwright** | — | — |
   138→| Erreurs | **Sentry** | — | — |
   139→| Hébergement | **Vercel** | — | Alternative : AWS Lambda + CloudFront |
   140→
   141→## 02.2 Architecture en couches
   142→
   143→```
   144→┌─────────────────────────────────────────────────────────┐
   145→│  EDGE : CDN mondial, cache HTML+médias, WAF,            │
   146→│         rate limiting, redirections, TLS                 │
   147→├─────────────────────────────────────────────────────────┤
   148→│  APP  : Next.js — RSC, ISR (articles), SSR (perso),     │
   149→│         Server Actions (admin)                           │
   150→├─────────────────────────────────────────────────────────┤
   151→│  API  : Route Handlers /api/v1/* (public, cachée)       │
   152→│         Server Actions (admin, authentifiées)            │
   153→├─────────────────────────────────────────────────────────┤
   154→│  JOBS : encodage vidéo, envoi e-mail, collecte SEO,     │
   155→│         sitemaps, agrégation stats, backups              │
   156→├─────────────────────────────────────────────────────────┤
   157→│  DATA : PostgreSQL (+ replica lecture) · Redis ·        │
   158→│         Meilisearch · S3/R2                              │
   159→├─────────────────────────────────────────────────────────┤
   160→│  TIERS: météo · vidéo · e-mail · données SEO ·          │
   161→│         analytics · push · régie externe                 │
   162→└─────────────────────────────────────────────────────────┘
   163→```

   507→# 06. MODÈLE DE DONNÉES
   508→
   509→## 06.1 Conventions
   510→
   511→- Identifiants : **UUID v7** (triables chronologiquement). Colonne `id uuid primary key`.
   512→- Horodatages : `timestamptz`, stockés en UTC. Colonnes `created_at`, `updated_at` sur toutes les tables.
   513→- Suppression logique : `deleted_at timestamptz null` sur toutes les tables de contenu. Toute requête de lecture filtre `deleted_at IS NULL`.
   514→- Nommage : `snake_case`, tables au pluriel.
   515→- Contraintes d'intégrité référentielle **déclarées en base**, jamais uniquement applicatives.
   516→- Index GIN sur les colonnes `jsonb` interrogées et sur la recherche plein texte.
   517→- Partitionnement mensuel sur `ad_events`, `email_events`, `page_views`.
